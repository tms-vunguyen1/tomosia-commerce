# Spec: AI Shopping Assistant Modal (UI-only)

> **Superseded**: this UI-only, fixture-driven mock was the first pass at the
> assistant modal. It has since been replaced by a real backend — see
> "Shopping agent" in `../../CLAUDE.md`'s Commerce agent decision record and
> `shopping-agent/README.md`. Kept here for history.

## Objective

Add a chat-style "Shopping Assistant" UI to the storefront, inspired by
`commerce-agents/examples/retail/storefront-web` but adapted to this repo's
constraints: it lives behind a floating action button (FAB) and opens as a
centered modal dialog — it is **not** a homepage/full-page experience like the
reference.

This is a **UI-only** deliverable. There is no real AI backend. All assistant
behavior is scripted/fixture-driven so the interaction can be reviewed and
iterated on before any backend integration is scoped as separate future work.

**User:** a shopper browsing the storefront who wants a taste of a
conversational shopping helper (ask a question, get a canned answer, see
example product recommendations).

**Success looks like:** clicking the FAB opens a centered chat modal with a
greeting and starter prompts; clicking a starter plays back a scripted
conversation (typewriter-streamed text, a loading/shimmer state, and — for
product-recommendation scenarios — fixture product cards with a working
"Add to cart" *UI* state); free-text input outside the scripted starters gets
an honest fallback message; the conversation persists while navigating the
site client-side and resets on full page reload.

## Tech Stack

- Next.js 16 (App Router), React 19, TypeScript.
- Tailwind CSS v4 (`@theme` tokens generated by `scripts/themeGenerator.mjs`
  into `src/styles/generated-theme.css` — never hand-edited).
- `react-icons` (already a dependency) for all icons.
- No new dependencies.

## Project Structure

New files, following the existing `cart/` component convention
(`src/layouts/components/cart/`):

```
src/layouts/components/assistant/
  AssistantButton.tsx     → FAB, fixed bottom-right, opens the modal
  AssistantModal.tsx      → centered dialog shell (overlay, close on Escape/backdrop/X)
  AssistantChat.tsx       → message list + input, owns conversation state
  MessageBubble.tsx       → single user/assistant message row
  ProductCard.tsx         → fixture product card (image, title, price, Add to cart)
  StarterPrompts.tsx      → the empty-state starter buttons
  script.ts               → the scripted starter → response mapping (text, delay, products)
  fixtures.ts             → static fixture product data (local images)
  types.ts                → ChatMessage, ScriptedResponse, FixtureProduct types
```

Mounted once in `src/app/layout.tsx`, alongside `Header`/`Footer`, inside
`Providers`, so it's available on every page and its state survives
client-side navigation:

```tsx
<Providers>
  <Header>...</Header>
  <main className="grow">{children}</main>
  <Footer />
  <AssistantButton />
</Providers>
```

`AssistantButton` owns the `isOpen` state and renders `AssistantModal` (which
in turn mounts `AssistantChat`), mirroring how `CartModal.tsx` self-contains
its own open/close state today.

## Code Style

Follow the conventions already visible in `CartModal.tsx` / `Header.tsx`:

- `"use client"` at the top of every interactive component.
- Function components, named exports default-exported, PascalCase filenames
  matching the component name.
- Tailwind utility classes inline, dark mode via `dark:` variants using the
  existing theme tokens (`bg-body`, `text-text-dark`, `border-neutral-200
  dark:border-neutral-700`, etc.) — no new CSS custom properties like the
  reference's `--ink`/`--card` (this repo's tokens already come from
  `theme.json` → `generated-theme.css`).
- Reuse existing `.btn` / `.btn-primary` / `.btn-outline-primary` classes
  (`src/styles/buttons.css`) for buttons instead of inventing new button
  styles.
- `react-icons/fa` (or `react-icons/hi2` for the sparkle glyph, e.g.
  `HiSparkles`) — consistent with existing icon usage across the codebase.
- Prettier with `prettier-plugin-tailwindcss` formats class ordering
  automatically — do not hand-order classes.

Example (button trigger, matching `CartModal`'s open/close pattern):

```tsx
"use client";

import { useState } from "react";
import { HiSparkles } from "react-icons/hi2";
import AssistantModal from "./AssistantModal";

export default function AssistantButton() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <>
      <button
        aria-label="Open shopping assistant"
        onClick={() => setIsOpen(true)}
        className="fixed bottom-6 right-6 z-40 flex h-14 w-14 items-center justify-center rounded-full bg-primary text-white shadow-lg transition hover:opacity-90 dark:bg-darkmode-primary"
      >
        <HiSparkles size={24} />
      </button>
      <AssistantModal isOpen={isOpen} onClose={() => setIsOpen(false)} />
    </>
  );
}
```

## Behavior Spec (from interview)

- **Icon & branding:** sparkle/AI glyph FAB, bottom-right, fixed across all
  pages. Assistant is labeled generically "Shopping Assistant" (not tied to
  the `Commerceplate` site name).
- **Modal shape:** centered dialog with backdrop overlay (not a side panel
  like `CartModal`). Closes on backdrop click, `Escape`, and an explicit close
  button. Responsive: comfortable fixed max-width/height on desktop
  (~ `max-w-lg`, `max-h-[80vh]`), near-full-screen on mobile.
- **Empty state:** greeting text + a row of starter prompt buttons (aim for
  3–4 starters, mirroring the reference's `Starters` component but with
  copy relevant to this storefront's catalog).
- **Scripted conversation:** each starter prompt maps to a fixed script
  (`script.ts`): a sequence of one or more assistant turns, each turn being
  either plain text or text + an array of fixture products. Free-text input
  that doesn't match a starter gets a static fallback message: something like
  *"I don't have real data for that yet — this is a UI demo."*
- **Loading state:** after sending a message, show a shimmer/skeleton
  "activity" line (e.g. "Searching the catalog…") for a short simulated delay
  before the response appears.
- **Response rendering:** assistant text streams in with a typewriter effect
  (character/word reveal via `setInterval`/`requestAnimationFrame`); product
  cards (if any) appear after the text finishes streaming.
- **Product cards:** fixture data only (`fixtures.ts`), reusing
  `/images/product-1.png` and/or `/images/image-placeholder.png` for images,
  made-up titles/prices. No link to a real product page. "Add to cart" is a
  local-only toggle: click → button becomes a disabled "Added" state with a
  checkmark. No call to `cartActions.ts`, no mutation of the real cart.
- **State persistence:** conversation state (messages, streaming progress,
  which starters have been used) lives in `AssistantButton`'s subtree at the
  layout level, so it survives modal close/reopen and client-side navigation,
  and resets on a full page reload (no `localStorage`).
- **Accessibility:** modal traps focus, restores focus to the FAB on close,
  `aria-label`s on the FAB/close button, `role="dialog"` + `aria-modal="true"`
  on the panel, messages announced via `aria-live="polite"` on the message
  list region.

## Testing Strategy

No test runner is configured in this repo. Verification is manual:

1. `npm run dev`, open the site, confirm the FAB renders on every page
   (home, a product page, a content page).
2. Click the FAB → modal opens centered, backdrop present, focus moves into
   the dialog.
3. Click each starter prompt → shimmer appears, then typewriter text, then
   (where scripted) product cards render with working local "Add to cart"
   toggle.
4. Type free text not matching a starter → fallback message appears.
5. Close via backdrop click, via `Escape`, and via the close button — all
   three work and focus returns to the FAB.
6. Navigate to another page (client-side link) with the modal's conversation
   populated → reopen the FAB → conversation state is retained.
7. Full reload (`F5`) → conversation resets to the empty/greeting state.
8. Toggle dark mode (`ThemeSwitcher`) → modal, FAB, and cards all render
   correctly in dark mode using existing theme tokens.
9. `npm run lint` passes with no new errors (in particular
   `react-hooks/exhaustive-deps`, which is an error in this repo's ESLint
   config).

## Boundaries

- **Always do:** reuse existing design tokens (`theme.json` /
  `generated-theme.css`) and `.btn` classes; keep `react-hooks/exhaustive-deps`
  clean; follow the `cart/` component folder convention for naming/structure;
  keep the feature entirely additive (no changes to `src/lib/shopify/**`,
  `cartActions.ts`, or auth cookie logic).
- **Ask first:** adding any new npm dependency (animation library, headless
  dialog library, etc.) instead of building the modal/focus-trap by hand;
  wiring the "Add to cart" button to the real cart; changing where the FAB
  mounts (e.g., into `Header.tsx` instead of root layout) if that turns out
  to be needed later; persisting chat to `localStorage`.
- **Never do:** call out to any real AI/agent backend (`commerce-agents/*` or
  otherwise) as part of this spec's scope; fetch real Shopify product data
  for the fixtures; make the assistant claim or imply it's a real AI when it
  hits the scripted fallback path; touch the unrelated in-progress changes
  already on this branch (`fix/auth-cookie-httponly` diff — `Announcement`/
  `TwSizeIndicator` removal, theme color changes, etc.).

## Success Criteria

- All 9 steps in Testing Strategy pass manually in the browser (light + dark
  mode).
- `npm run lint` and `npm run build` succeed with no new errors/warnings.
- No file outside `src/layouts/components/assistant/` and the single mount
  point in `src/app/layout.tsx` is modified.
- No new npm dependency added.
